# Часть 2. Добавление исключений

Ветка: `part2-exceptions`

Класс `DynamicArray` (динамический массив `int`) из части 1, в котором возврат кодов ошибок (`bool`) заменён выбросом исключений **конкретных типов** из стандартной библиотеки. Допустимые значения элементов — **−100…100** включительно.

## Выполненные задания

| Ситуация | Тип исключения | Где возникает |
|----------|----------------|---------------|
| Ошибка выделения памяти | `std::bad_alloc` | `new[]` в конструкторе, конструкторе копирования и `push_back` |
| Индекс вне границ массива | `std::out_of_range` | `set`, `get` |
| Значение вне промежутка −100…100 | `std::invalid_argument` | `set`, `push_back` |

### Что изменилось по сравнению с частью 1

- `void set(int index, int value)` — вместо `bool` ничего не возвращает; при ошибке пишет исключение.
- `int get(int index) const` — теперь возвращает значение напрямую, а не через ссылку; при выходе за границы пишет `std::out_of_range`.
- `void push_back(int value)` — при недопустимом значении пишет `std::invalid_argument`.
- Появились новые методы `checkIndex(int)` и `checkValue(int)`, которые выполняют проверки и пишут исключения.
- Остальной интерфейс (`print`, `size`, конструктор копирования, `add`, `sub`) без изменений.

## Демонстрация

`src/main.cpp` через `try` / `catch` показывает срабатывание всех трёх типов исключений:

- `std::out_of_range` — вызов `a.get(5)` для массива из 3 элементов;
- `std::invalid_argument` — вызов `a.set(0, 101)` (при этом `a.set(0, 100)` проходит: граница входит в диапазон);
- `std::bad_alloc` — попытка создать массив заведомо недоступного размера.

После этого проверяется, что операции из части 1 (`push_back`, конструктор копирования, `add`, `sub`) продолжают работать.
